# Asimi security reporting

Use GitHub's [private vulnerability report](https://github.com/Axiu112530/Asimi/security/advisories/new) when enabled. If it is unavailable, contact the maintainer through an existing private channel. Keep vulnerability details out of public issues and pull requests. Include the affected version, the safety boundary, and a reproduction using an isolated project or the dedicated test host. Include redacted logs where useful.

Use the explicit per-action approval flow when testing behavior. [Release security review](docs/release/SECURITY-REVIEW.md) · [Privacy notice](PRIVACY.md) · [Historical 0.2 security review](docs/0.2/SECURITY-REVIEW.md)
