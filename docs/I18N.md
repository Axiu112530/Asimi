# DeskPilot AI — Internationalization

Status: Phase 1 bilingual UI implemented; final section records current evidence.
The earlier design/Phase 0 checks are retained as background and future gates.
Use Vue 3 Composition API with Vue I18n, TypeScript and JSON resources. Pinned
probe versions: Vue 3.5.45, Vue I18n 11.4.18, TypeScript 7.0.2, Vite 8.3.7.
Compatibility is scoped to the tested Node 24.21.0 and Go/Wails/WebView2 stack.

## Locale policy and resources

Supported at first release: en-US (English default), zh-CN (Simplified Chinese).
Reserve ja-JP and zh-TW; do not expose incomplete locales. Never derive first-start
language from Windows, browser `navigator.language` or geographic location.

```text
frontend/src/locales/
  en-US.json
  zh-CN.json
```

Product key namespaces: app, navigation, tasks, models, capabilities, computer,
approvals, security, settings, errors, common and accessibility. Keys describe
meaning rather than English wording. Resource trees have identical leaf keys and
matching interpolation parameters. CI rejects missing/extra keys and placeholders.
Proper product/provider/model IDs are data, not translated UI sentences.

Initialize `createI18n({legacy:false,locale:savedOrEnglish,fallbackLocale:'en-US',
messages})` only after local settings load; show a neutral boot surface until
the persisted preference is known. Use the global Composer for shared UI so
`locale.value` updates all views without restart. Independent local composers
must inherit the global locale. Vue I18n documents [global scope and live locale
changes](https://vue-i18n.intlify.dev/guide/essentials/scope).

## Persistence and failure behavior

Settings stores `appLanguage` in SQLite with explicit supported-locale validation.
No saved value means en-US. A UI switch saves through a narrow Go configuration
service, then updates the global locale and document/window/menu language. If
the write fails, show a localized storage error and retain/revert to the last
persisted choice; never claim the next launch will restore an unsaved preference.
Unsupported/corrupt saved values fall back to en-US with a diagnostic code.

The Phase 0 Wails harness reads/writes a settings row in its own disposable
SQLite database. Its two-process test checks initial English, live Chinese,
saved Chinese after exit/relaunch and return to English. The production settings
service, corruption/write-failure behavior and native menus are later work.

## Copy and error rules

All labels, menu/window titles, buttons, confirmations, notifications, tooltips,
ARIA text, placeholders, empty/loading states and errors use resource keys.
Go returns `{code,params,detailsRef}`; examples: `security.denied`,
`approval.expired`, `provider.capability_unverified`, `storage.write_failed`.
The UI owns explanatory sentences and sanitized parameter formatting. Unknown
codes show a localized generic message plus a support code, not raw Go errors.
Technical logs use stable codes, independent of UI locale. User-authored content
and historical task messages remain unchanged. Rich text must use safe component
interpolation; never render translations or model output as unrestricted HTML.

Use Intl for date/time, numbers and currencies; store UTC timestamps, display in
the user's selected/system timezone with a visible timezone where relevant.
Pricing data includes currency and effective date; no currency conversion is
implied by language switching. Avoid sentence concatenation, positional assumptions,
text-width limits and English-only plural rules. Native dialogs should be app-owned
localized UI where practical; OS-owned UAC wording follows Windows.

## Agent response language

Persist a separate enum: `follow-app`, `auto`, `en-US`, `zh-CN`.
Priority: explicit current-task language → independent setting → follow-app value;
auto detects the task language and asks only on meaningful ambiguity. Follow-app
defaults to English for English UI and Simplified Chinese for Chinese UI. Inject
this as response presentation metadata, never as security policy. UI switching
affects future responses following the app; it does not rewrite history, reset
task IDs, clear context or restart running tools. Task-specific overrides remain.

instead of banning every string literal. Translation review is required for each
new feature. English README/docs remain primary with a Chinese entry.

## Phase 1 implementation and evidence

Product resources now live at `frontend/src/locales/en-US.json` and `zh-CN.json`;
the isolated Phase 0 resources remain unchanged. The product has **396 matching
leaf keys** with checked placeholder parity and nonempty translations. A source
check validates 194 literal translation uses and an actual missing-key fallback.
Resource ownership covers navigation, all pages, inspector, security/error/audit
codes, approvals, status text, empty/loading states, notifications, titles, tooltip
and accessibility labels. Unknown error codes use a translated generic message
with the stable support code. Proper provider/model IDs and user-authored messages
remain data.

SQLite AppSettings persists language, independent Agent language, theme and startup
behavior. A neutral boot surface avoids displaying the wrong saved locale. The
global Composer and document title/lang update immediately; native change events
also refresh settings when changed through a business call. System language never
selects the app language. Agent-generated conversation text uses the task's chosen
language and is preserved verbatim on UI switching.

Native acceptance proved English first launch, live Chinese, separate Chinese Agent
reply under English UI and English reply under Chinese UI, saved Chinese/Agent
preference after restart, and unchanged message history. Both languages and
light/dark themes were rendered in the app's own WebView at 1380×820, 1000×700 and
900×620 without document horizontal overflow. This is targeted layout evidence,
not comprehensive screen-reader, pseudo-locale or every-string visual regression.

## Phase 2B additions

Provider/model management, API-key presence and errors, capability facts, selected
image warnings, real Assistant, Playground, request statuses and Usage use the
same en-US/zh-CN resources. Original 414 Phase 2A keys are preserved. New network
and credential errors are stable Go codes translated in Vue. Unknown token/cost
fields display unknown rather than a fabricated zero. Agent response language
continues to be independent of the interface language and original history text.
The Phase 2B verification record contains the final parity/key-use check result.

## Phase 2C additions

The English and Simplified Chinese resources cover the Computer page, display
geometry, preview, crop and privacy mask, upload review, vision results, and
metadata history. Screen error codes follow the existing native-to-Vue
translation path. The Phase 2C verification checks parity and preserves
all 605 Phase 2B keys.
