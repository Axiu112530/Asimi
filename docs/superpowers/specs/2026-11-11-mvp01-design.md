# DeskPilot AI MVP 0.1 integrated design

The user supplied the complete product brief and explicitly authorized continuous implementation followed by unified acceptance. This document records that scope; it adds no module approval gates. Work stays on the current dirty branch, without commits, pushes, branch switches, historical migration edits or historical evidence deletion.

## Product and architecture

Retain the existing Go/Wails 3.1.0, Vue 3, provider adapters, DPAPI, screen review, semantic UIA approval chain, SQLite WAL and window-first shutdown. Add an integrated Home/onboarding, Developer/Workspaces, Tasks and Skills surface. English remains the default; every new static string has Chinese parity.

Use an additive v5 migration for workspace registry, agent task state, skill enablement and product action journal. New file and command actions use immutable server-side proposals, complete argument hashes, expiry, single consumption, execution intents, independent verification and audit. Existing computer actions retain their proven chain and are described in the common tool catalog rather than routed around it. Unknown results never replay. Filesystem, process and network I/O remain outside database transactions.

Workspace registration is accepted only from an explicit native directory selection. Bound scans by depth, count, bytes and exclusions. Reject traversal, absolute child paths, alternate streams, symlinks and reparse points. File changes display exact before/after and diff, revalidate original content and target identity, atomically replace one approved file, retain recovery evidence and reread for verification. No delete or bulk overwrite.

Commands resolve fixed registry IDs to executable and argument arrays. No shell binding. Display cwd, executable, arguments, timeout, output budget, code execution and network risk. Use a Windows Job Object, kill-on-close, process/memory/CPU bounds and cancellation. Installation requiring elevation remains manual. Network-dependent operations require explicit network consent; do not claim a Job Object provides network isolation.

Agent Tasks are separate from ordinary chat. Persist plans and individual steps, stop/pause/resume/cancel, summary and recovery state. Read-only project/environment steps may advance automatically; file/command/computer effects require individual approval. Provider-generated text remains untrusted and cannot grant permissions.

Notepad is limited to positively identified supported Microsoft packaged Notepad, a single unambiguously blank UIA editor with ValuePattern, complete target revalidation, semantic input and independent reread. Never use global input fallback. Real Notepad acceptance must be initiated by the user in the final application; until then this remains CONDITIONAL.

## Acceptance

Preserve historical reports and 844 bilingual keys. Run new security and recovery tests during implementation, then the full Go suite, vet, dependency checks, frontend tests/typecheck/build and final packaged native acceptance. Separate simulated/fake, native Windows and real provider evidence. External model calls are opt-in only. Do not use credentials merely because present in the environment. Preserve 1412 CHARACTERIZED. Deliver a complete portable directory plus guides and honest per-feature statuses; unverified Windows versions remain unverified.
