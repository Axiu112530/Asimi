Agent 与执行器分离。每轮模型仅产生受约束的规划数据。未知类型、多个副作用、超预算、源文件变化和错误哈希会阻止提案。发给 Provider 的源代码、测试输出和视觉内容由用户审阅其范围。已完成文件或测试的结果进入下一轮，下一轮涉及新披露时再次审阅。用户审批只对应单个现有执行链动作。StopAll 取消模型和动作，运行中断后保留状态，已消耗或未知动作不得重放。

关键验收是自然语言修复隔离 Go 项目的真实问题。通过产品流程生成可审阅 Diff，批准事务写入和定向测试，将真实测试结果交回模型并生成报告。区分 Go 测试、回环夹具、Windows 原生、真实 Provider 和手动用户验收。检查任务暂停、恢复、过期、目标变化、网络或存储错误、双语和资源释放。真实桌面或 Notepad 验收等待用户手动选择和批准，未通过的场景明确标记。
