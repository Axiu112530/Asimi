# DeskPilot 0.2 开发助手

1. 在 **Workspaces** 选择一个本地固定盘目录。在 **Developer** 查看文件、符号和依赖，确认项目的测试方式。
2. 在 **Tasks** 选择该目录和具备美元费率的 BYOK 模型。写明预期行为、相关文件和测试范围。选择少量必要文件。
3. 审阅模型请求中的代码和日志范围，再确认发送。检查提案的精确 Diff、原始哈希和目标路径。每个文件分别审批。
4. 文件核验后审阅下一轮。定向测试由模型从允许模板提议，用户确认网络风险并逐命令批准。检查退出码、超时、取消和分流后的输出。
5. 审阅真实测试结果和下一轮请求。模型可解释结果并生成报告，或提出新的独立修改。最终总结和实际执行状态都保存在任务中。

本地项目上下文包含项目类型、依赖清单、候选路径、所选源文件、符号及测试指导。源文件最多四个，过大的文件只提供有限片段。常见密钥、连接字符串、敏感目录和私人证书文件不自动送出。截断或遮盖的源文件不能直接产生自动替换提案。Git 状态和差异可在 Developer 中使用原有固定命令单独检查。

文件替换继续采用本地 NTFS 事务和恢复副本。可用的长期替代方案是先写完整文件并通过 `ReplaceFileW` 发布，再用可恢复日志协调结果。然而本机锁测试显示，该方式不能绕过用于绑定目标身份的拒绝写入句柄。未来替代必须验证并发写入、重命名、重解析路径、崩溃和中途断电后的目标身份及恢复，才可替换当前 TxF 门槛。参考 [Microsoft 的 TxF 替代建议](https://learn.microsoft.com/en-us/windows/win32/fileio/deprecation-of-txf)。

Job Object 限制进程树、运行时间、内存、CPU 和输出。项目代码仍以普通用户权限运行。命令配置关闭常见运行时的依赖下载，模型调度器不允许依赖恢复命令。缺少运行时或依赖时，先在开发环境补齐，按真实项目情况重新审批。
